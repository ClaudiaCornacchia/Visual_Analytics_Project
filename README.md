# Explainability of Text Embeddings through Semantic Perturbations and Visual Analytics

## Introduction
Large Language Models (LLMs) map text into high-dimensional vector spaces, but their internal representations often act as "black boxes". This project provides an interactive, human-in-the-loop **Visual Analytics framework** designed to diagnose and test the robustness of text embeddings. 

Applied to the **Twitter US Airline Sentiment dataset** (comprising over 10,000 real-world customer service interactions), the system combines dimensionality reduction, topic modeling, and real-time semantic perturbations (like Leave-One-Word-Out ablations and targeted structural attacks), the system allows data scientists and NLP researchers to visually evaluate whether geometric clusters are formed based on true semantic meaning or superficial structural shortcuts (e.g., airline names, @mentions, or courtesy markers).

### Techniques and technologies used
* **Embedding model:** `Qwen3-Embedding-0.6B` (executed on Kaggle via NVIDIA Tesla T4 GPU).
* **Dimensionality reduction:** `UMAP` (Uniform Manifold Approximation and Projection) to map 1024-D vectors into a 2D topology.
* **Topic modeling and keywords:** `BERTopic` (c-TF-IDF) for global semantic clustering and local `TF-IDF` for neighborhood keyword extraction.
* **Frontend visualization:** `D3.js` and `JavaScript` for interactive DOM manipulation, SVG rendering, and real-time trajectory animations.
* **Backend and API:** `Flask` backend hosted on Kaggle, securely exposed to the local frontend using an `Ngrok` tunnel.



## Repository structure
* `index.html`: The main entry point of the dashboard.
* `app.js`: Contains all the frontend logic, D3.js visualization scripts, and API fetching mechanisms.
* `base_map.csv`: Contains the pre-computed 2D UMAP coordinates of the initial high-dimensional embeddings. It allows the frontend to instantly render the global scatterplot without re-running heavy dimensionality reduction algorithms.
* `bertopic_data.json`: Stores the pre-calculated global topic models and top representative keywords generated by the BERTopic (c-TF-IDF) pipeline. It is used to populate the interactive diagnostic panels.
* `code/myvisualanalytics.ipynb`: The backend Jupyter Notebook to be executed on Kaggle. It initializes the models, sets up the Flask server, and handles real-time embedding perturbations.
* `code/results_scripts`: A collection of standalone Jupyter Notebooks used to reproduce the quantitative results discussed in the report (e.g., Silhouette Scores, Leave-One-Word-Out ablations and structural perturbation benchmarks)



## Setup and execution guide

The application operates with a separated architecture: the heavy embedding model runs on a cloud GPU (Kaggle), while the visual interface runs locally in your browser.

### 1. Kaggle Backend and Ngrok setup

To establish a real-time communication link between the local browser and the Kaggle GPU, we use Ngrok.

#### Get your Ngrok Token
1. Go to [ngrok.com](https://ngrok.com) and sign in (or create a free account).
2. On the left-hand menu of your dashboard, click on **Getting Started** → **Your Authtoken**.
3. Click the **Copy** button to copy the authentication token string.

#### Store it securely in Kaggle
1. Open the Kaggle Notebook.
2. At the top of the screen, click on the **Add-ons** menu.
3. Select **Secrets** from the dropdown.
4. A side panel will open. Click **Add a new secret**.
5. In the **Label** field, type: `NGROK_TOKEN`.
6. In the **Value** field, paste the token you copied from ngrok
7. Click **Save**, and ensure the toggle switch next to your new secret is set to **Attached** (grants the notebook permission to read it)

> **Warning**: University networks like Eduroam might block Ngrok connections. If you experience connection issues, consider using a different network (e.g., mobile hotspot).


### 2. Local Frontend execution

To connect the frontend to the Kaggle backend, open the `app.js` file and replace the `DEFAULT_API_BASE_URL` variable at the top of the file with your newly generated Ngrok URL (you will find it printed in the output of the last Kaggle cell)

### 3. Run the application
Launch `index.html` using a local web server. You can do this using either of the following methods: 
- Use the *Live Server* extension in Visual Studio Code
- Use Python's built-in HTTP server. Open your terminal in the project directory and run ``` python -m http.server ```,
then  open your browser and navigate to http://localhost:8000

### Input Files Management

To avoid recalculating embeddings and other processed data during every execution, these files are stored as inputs within the environment. The system will automatically check for their existence before triggering any new computation:

## Visualizations and interactions

### 1. Interactive Global space and coordinated panels
The primary interface is an interactive 2D UMAP scatterplot featuring dynamic color encoding (Airline, Sentiment, or Topic). The map is bidirectionally linked with two semantic diagnostic panels:
* **BERTopic (Global topic modeling):** Extracts and labels underlying semantic clusters across the entire dataset using c-TF-IDF. Selecting a topic highlights all its corresponding tweets on the scatterplot. Additionally, clicking a keyword within a topic's chart filters the map to brighten only the tweets containing that exact word.
* **TF-IDF (Local keyword extraction):** Dynamically identifies the most distinctive keywords for a custom user selection. Brushing a group of tweets triggers the backend to compute the TF-IDF chart for that specific subset, and clicking a keyword instantly highlights the tweets containing that word on the map.

### 2. Single-node word Heatmap
Clicking an individual tweet opens an inline heatmap that evaluates the "semantic weight" of individual words. 
* The system calculates the embedding shift by temporarily removing each word (Leave-One-Word-Out ablation) to measure how drastically the cosine similarity changes. 
* **Visual Encoding:** A sequential color scale is used to map the impact. **Bright Yellow** indicates a high semantic shift (the word acts as a "semantic pillar"), while **Dark Blue** indicates low or no impact on the overall meaning.
* **Interaction:** Clicking a colored word selects it as the target for the perturbation panel.

### 3. Active perturbations 
Users can actively stress-test the embedding model using word-based manipulations (Synonyms, Antonyms, Custom words), LLM-based transformations (Paraphrasing, Opposite), or structural noise (Typos, Word Shuffle, Leetspeak). 
* **Dynamic drift trails:** When a perturbation is applied, the system draws a visual trajectory arrow on the scatterplot from the original tweet's position to its new perturbed coordinate. 
* **Frozen UMAP projection:** To precisely isolate the effect of the perturbation, the system avoids recalculating the entire dimensionality reduction map. Instead, it calls the `.transform()` method on the pre-trained `umap_mapper`. This projects the newly generated high-dimensional vector directly into the stable, existing 2D coordinate space, guaranteeing that the visual arrow accurately reflects only the pure semantic drift caused by the attack without destroying the baseline geometry.

### 4. Selection Framework
To effectively navigate the dense UMAP projection, the dashboard features a flexible 2x2 selection framework. Users can independently combine two interaction tools with two different selection scopes, and the system will dynamically adapt its visual cues and diagnostic panels based on the active combination:

**1. Interaction Modes (How to select):**
*   **Click:** single-coordinate interaction targeting an individual tweet.
*   **Brush:** allows users to drag a bounding box to select an arbitrary area of the map.

**2. Selection Scopes (What to include):**
*   **Point-Based:** Limits the selection exactly to the user's physical interaction. It isolates only the specific clicked node or strictly the tweets enclosed within the brushed bounding box.
*   **Cluster-Based (Semantic expansion):** It automatically expands the user's input to include the entire cluster of the targeted nodes.

Visual outputs:
*   *Point + Click:* Opens the single-node heatmap for word ablation.
*   *Point + Brush:* Extracts local TF-IDF keywords and comparative subset histograms strictly for the drawn area.
*   *Cluster + Click/Brush:* Highlights the entire macro-cluster.
